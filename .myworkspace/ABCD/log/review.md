# Judgement review: ABCD (Ram's Portfolio)

Reviewer: independent QA-lead review on the live development server (http://127.0.0.1:5173), 2026-11-08 around 11:00 local time, as Sourav, Brijesh and Ram, driven with Python Playwright plus API checks (`/api/hexa/tests`, `/api/hexa/runs`, `/api/stories`, `/api/context`, `/api/huddle`, `/api/usage`). Ground truth: `log/backlog-notes.md`, `log/ci-runs.md`, `team.json` and the two clones. Screenshots are in `log/review-shots/`.

## Verdict

**Not yet trustworthy for UAT sign-off on this portfolio.** The mechanics are sound. The strict rule ("covered only when a linked automated test passed in the target build") is applied as written. Linking a real CI test turns the criterion Covered with the right commit. Approval cards lock for the wrong manager. Guards and CloudOps honesty hold. The judgement has gaps, though:

- The rule counts *any* linked test, whatever its repository. ABCD-1004 AC2 (paymentservice) reads **Covered** because two moov-io/ach tests are linked to it.
- The `ach-core` component resolves to none of the 2,211 ach tests. Because of that, Hexa's component view and the specialists both act as if ach-core has no automated evidence. One answer told Brijesh that it has "no record" of the ach run and speculated why a test that passed had failed.
- For the six stories whose criteria literally name passing Go tests, the analyst reports "No test" or "Not run yet". It drafts manual UAT cases and offers to "Write automation for the gaps" without ever pointing at the matching tests.
- A manager who cannot approve can supersede the pending approval of the manager who can.

## What worked well

- **The strict coverage rule as written.** Manual-only criteria are "Not run yet", never Covered. The report footnote states the rule. After Brijesh linked `TestFile__AscendingBatchSequenceADV` to ABCD-1014 AC4 and re-analysed, AC4 turned **Covered: TC-C8BEE1B55A passed in PR #1922 (c7025ec, master)** (right test, commit and run), and the card dropped AC4 from the proposals. Counts on every report matched the links in `/api/hexa/tests` (1004: 1/0/4/0; 1014: 0/0/3/2 then 1/0/3/1; 1006: 0/0/3/2; 1009: 0/0/5/0).
- **Status awareness for In Progress and To Do.** ABCD-1004 and ABCD-1003 are labelled "not a UAT candidate yet" (the R06 fix holds).
- **Approval governance.** Sourav's card on an ach-core story is locked, and the card names who can decide. Brijesh's approval wrote exactly one manual test (UAT-ABCD-1014-AC2), linked to the story, criterion and component. Superseded revisions are marked. Ram can read but not post in others' chats.
- **Honest CloudOps.** Q6 refused to invent restarts or p95, said the README `kubectl` output is illustrative, and listed the checks it would need. It promised GitOps PRs, not cluster changes.
- **Q2 (checkoutservice) and Q5 (currencyservice)** were factually right against Hexa and the README.
- **App Context.** Both clones are indexed (378 + 245 passages), retrieval is hybrid and ready, and citation anchors land on the cited passage (`chunk-348` gets the `target` class and is scrolled into view).
- **Hexa runs** show the 3 local CI runs with the correct totals. "1.0 s of test time" is labelled as test time, not wall time. Search by Go name (`TestIssue1901`, `Writer_writeLine`) works.
- **Huddle** groups duplicate risk items ("Similar to … and 1 more open"). **Agents** shows per-agent tokens and the rejected call. **Phone**: no horizontal page scroll on any page tried; the report has Chat/Report tabs.
- No console errors, 5xx responses or placeholder text were recorded by the persona observers during the whole review.
