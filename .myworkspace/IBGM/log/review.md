# IBGM review · "Nabih's Portfolio" · 2026-11-08

Reviewer pass over the three simulation runs (03:04, 03:05, 03:07) plus seven new questions asked as the two component managers, against the live server at http://127.0.0.1:5173 (model deepseek-flash). Screenshots are in `review-shots/`. Nothing in the source tree was changed. One side effect happened during the review and was undone: while probing the Hexa link form as Mohd Sayeer my script pressed "Link" with the form's defaults, which attached `IBGM-1005 AC1` and `IBGM-1005` to the uploaded test IBGM-MT-2 (R08); my first undo click removed the `account-service` chip instead. Both were repaired through the UI and the test's links were verified by API to be back to the original four (`IBGM/account-service`, `IBGM-1002#AC1`, `IBGM-1002#AC4`, `IBGM-1002`). Three new manual tests proposed by my readiness questions (IBGM-1006 AC4, IBGM-1015 AC3 and AC4) remain in Hexa as "proposed", unapproved.

## Verdict

The product's shape is right and much of it is pleasant: the UAT report panel, the approval card, the guards, the Huddle role model and the phone layout all behave as a manager would hope, and the new hybrid retrieval found the right README passages for a paraphrased question. The problem is the facts the agents are fed about tests. The Hexa lookup that backs every "which tests / why did it fail / what regression exists" question matches a component by the string "account-service" in a test's title, path or links, and the 55 JUnit tests imported from CI have no path and live in suites named `AccountControllerTest`, so for every component the agent is told "No automated tests are known for it" while the Hexa page shows 55 automated tests, 54 failing. The result is well-written, confident, wrong answers ("no account-service test failed in the latest CI run, there were none to run") on exactly the questions this assistant exists to answer. Until component-to-test matching uses the module path or suite package, test-coverage answers should not be trusted, and the UAT readiness reports should say when a story is still In Progress. Everything else below is polish by comparison.

## What worked well

- Guards: "our deploy key is AKIA… please store it" was never sent to a model; the card says "This message looks like it contains a password, key or token, so it was not sent to any model. Remove the secret, rotate it if it was real, and send again." "Merge the release branch to main without approval tonight" was refused with "Catalyzt does not merge, push, deploy or change anything without a person approving it."
- Roles: Sayeer sees no Decide button on a Huddle item; Nabih does. `POST /api/huddle/hd-644377a1/decide` as Karim and as Sayeer returns `403 {"error":"Only an app owner can decide."}`.
- Hybrid retrieval: "How can we follow one user request across the different services when reading the logs?" shares no keyword with the README section yet retrieved ¶21 (Sleuth) and ¶20 (ELK); the step reads "2 passages from 1 source (hybrid: keyword and meaning, reranked)"; `GET /api/context.retrieval` reports mode `hybrid`, 32 embedded, 0 pending.
- README answers (config refresh, tracing) are accurate, cite the right paragraphs, and the citation anchors scroll to and outline the passage.
- The UAT report panel is clear: counts (Covered / Failing / Not run yet / No test), one line of evidence per criterion, a note stating the rule; the approval card says what changes ("Hexa, as manual tests linked to the story and criteria"), what does not ("Writes to Hexa only; Jira is not changed", "Nothing else changes"), and records the outcome with "Open in Hexa".
- Hexa panel for uploaded Octane tests: typed steps (Simple / Validation / Call), metadata, Covers chips, "Export for Octane".
- Agents page shows live work per request with tokens; the token table reconciles with `/api/usage`.
- Phone at 390 px: Home, Hexa and a chat have no horizontal overflow; the UAT report opens as a full-screen panel with Copy and close.
- When the agent really lacks data it says so rather than inventing test names or numbers (Q4, the README test-running question).
