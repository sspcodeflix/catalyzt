# WIMT judgement review (Jacques's Portfolio)

Reviewer: independent QA-lead pass, 2026-11-08, live dev server http://127.0.0.1:5173, as Hitesh, David, Robin and Jacques (Playwright, 1360 px and 390 px). API answers were checked against `GET /api/hexa/tests`, `/api/hexa/runs`, `/api/stories`, `/api/context`, `/api/huddle`, the CI result files in `results/` and `log/backlog-notes.md`. I made no source edits and did not touch the database. I used 10 model requests (4 UAT analyses and 6 questions). Screenshots are in `review-shots/`.

## Verdict

**I would not use WIMT's readiness numbers for sign-off yet.** The mechanics work: analysis, Analyse again, linking and unlinking with undo, approval rights on the server, guards, the phone report view. The evidence underneath them is wrong in both directions:

- **Real results are missed.** None of the 787 CI results (767 Ghostfolio Jest, 20 Petclinic JUnit) maps to any component. So "which tests cover portfolio-api / api-gateway" gets the answer "no automated tests". The answers even suggest writing tests that already exist and passed.
- **Unrelated results are counted.** Leftover word-matched links let a Petclinic test "cover" a Ghostfolio criterion, and the reverse. The app counts those as passing evidence. As a result the In Progress bug WIMT-1011 shows AC1 as covered.
- **Ghostfolio's documentation can't be found.** Its App Context is entirely CHANGELOG passages, so a documentation question about Ghostfolio cannot be answered.

The one link I made by hand (PetResourceTest to WIMT-1009 AC1) worked. AC1 went to Covered with the right build (`local-e8b747a-maven`, e8b747a, main), and the link came off cleanly.

## What worked well

- **Linking end to end.** I linked `TC-C20B965974` (PetResourceTest.shouldUpdatePetUsingPathIdWithoutBodyId) to WIMT-1009 AC1 from the Hexa test panel and ran Analyse again. AC1 went to **Covered**, with "TC-C20B965974 passed in run local-e8b747a-maven (e8b747a, main)", and the counts changed from 0/0/5/0 to 1/0/4/0. The Unlink buttons, with an Undo toast, removed both the criterion link and the story link; the API confirms `links: []`.
- **Analyse again** gives a fresh report in about 2 s. It is deterministic: the UAT analyst uses no model, only the router does. In Progress and To Do stories are labelled "not a UAT candidate yet".
- **Approvals.** The server enforces F19: Robin got a 403 with a clear message. David, the right manager, had a locked card until he rated, then approved. "Added 5 manual tests to Hexa, linked to WIMT-1006", with component and criterion links. The card states "Writes to Hexa only; Jira is not changed".
- **Honest refusals.** Q3 said plainly that its sources are changelog-only and named the files it would need. Q5 refused to invent a production error rate and said where to look.
- **Huddle** groups the four repeated risk items ("Similar to ... and 2 more open").
- **Agents page** shows each request's agents, model and tokens; usage totals add up (92 to 110 calls over this review).
- **Phone (390 px)**: home, tickets, story, chat, the Chat/Report tabs, Hexa runs, Context, Huddle, Agents and Search have no horizontal scroll. The report view is clean (screenshot `34-phone-report.png`).
- **Petclinic App Context** is indexed well: the compose, pom and README passages are retrievable.
